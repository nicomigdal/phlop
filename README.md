# פלופ · Flop

אפליקציית פוקר לחברים, בעברית וב־RTL, עם עיצוב כהה, תמיכה בטלפונים ופרסום חינמי ב־GitHub Pages.

## מצב הגרסה

הגרסה עובדת **מקומית במכשיר אחד** כברירת מחדל. מצב מקומי מסומן בכל המסכים ואינו מסנכרן בין מכשירים.

המשתתפים קבועים ומוגדרים ב־`ROSTER` שב־`src/domain.js` (שם + מספר טלפון). הכניסה היא במספר טלפון וסיסמה. הסיסמה הראשונית של כולם היא `123`, ובכניסה הראשונה חובה לבחור סיסמה חדשה. הכניסה נשמרת במכשיר, כך שבפתיחות הבאות אין צורך להתחבר שוב. במצב מקומי אדמין יכול לאפס סיסמה של חבר לסיסמה הראשונית מעמוד הניהול.

חיבור Firebase Auth + Firestore מוכן בקוד, אך **אינו פעיל עד יצירת פרויקט, הגדרת קבוצת החברים ופרסום כללי הגישה**. אין SMS ואין Supabase. אין שרת בתשלום. ניתן להשתמש במסלול Firebase Spark ללא כרטיס אשראי, בכפוף למכסות החינמיות שלו. חיבור לענן דורש חשבון Google של בעל האפליקציה. אין להפעיל Blaze או לקשר חשבון חיוב.

כתובת הפרסום המיועדת: https://nicomigdal.github.io/phlop/

## מה עובד

- פתיחת ישיבה עם מיקום (אצל אחד החברים שמארחים או מיקום חופשי; יובל ודני אינם מופיעים כמיקום), כניסות נוספות והעברת אירוח. ישיבה מזוהה לפי התאריך והמיקום, ושעת ההתחלה היא שעת הפתיחה.
- הצטרפות לשולחן פתוח מכרטיס "השולחן הפעיל" במסך הבית בלבד (אין קודי הזמנה).
- סיום ערב, חישוב תוצאות, חלוקה דטרמיניסטית של הפרש באגורות ואישור מפורש.
- הצעת העברות, עריכה ידנית/פיצול/איחוד עם אימות ההתאמה לתוצאות. האלגוריתם מעדיף התאמות מדויקות ואז יתרות גדולות; אינו מבטיח מינימום מתמטי גלובלי.
- כפתור "העברה בביט" לכל חוב פתוח שלי: מעתיק את מספר הטלפון של הנושה ופותח את אפליקציית ביט. לביט אין קישור ציבורי שממלא נמען וסכום מראש, ולכן מדביקים את המספר ומזינים את הסכום ידנית.
- ניתן להתקין את האפליקציה למסך הבית (PWA): Chrome באנדרואיד ← תפריט ⋮ ← "התקנת אפליקציה"; ב־iPhone דרך Safari ← שיתוף ← "הוספה למסך הבית".
- קיזוז חובות לזוג שחקנים, בקשות לחוב ידני, תשלום חלקי/מלא ואישור/דחייה של הצד השני. ביטול אפשרי רק ליוזם.
- תיקון תוצאות סגורות בידי אדמין באמצעות פעולות היפוך והוספה. תשלומים שכבר אושרו נשמרים.
- מרכז התראות פנימי, תזכורת חוב לכל חבר לכל היותר פעם ביום, היסטוריית בקשות ויומן פעולות.
- סטטיסטיקות המבוססות על תוצאות משחק בלבד, שני דירוגים, גרפים, השוואה בין חברים, סיכום לפי חודשים ורווח/הפסד לפי מיקום הערב.
- פרופילים, סינון ישיבות לפי שחקן/מיקום, גיבוי ושחזור JSON המאומת מול יומן הפעולות.
- מניעת כפילויות באמצעות מזהי פעולה, בדיקת גרסת הישיבה בעת סגירה, בדיקה חוזרת של יתרה בעת אישור תשלום.

## הפעלה מקומית

נדרש Node.js 22.12+ (מומלץ 24).

```sh
npm ci
npm run dev
npm run demo
npm test
npm run build
npm run preview
```

`public/firebase-config.json` מכיל `{}` כברירת מחדל. במצב זה האתר אינו פונה ל־Firebase. הנתונים נשמרים במפתח `phlop:data:v1`, וסיסמאות מקומיות נשמרות כ־SHA-256 עם מלח במפתח `phlop:auth:v1` (מחוץ ליומן הפעולות).

### גרסת הדגמה עם נתונים סינתטיים

לחיצה כפולה על `Flop Demo.cmd` בתיקיית הפרויקט (או `npm run demo`) מפעילה את האפליקציה בכתובת http://127.0.0.1:5174 עם נתונים סינתטיים: עשרת המשתתפים האמיתיים, 16 ערבים סגורים במיקומים שונים, חובות פתוחים, בקשות ממתינות ושולחן פעיל להצטרפות. ההדגמה נכנסת אוטומטית כניקו, מאפשרת להחליף שחקן בעמוד הפרופיל, ונשמרת במפתחות נפרדים (`phlop:demo:v1`) כך שאינה נוגעת בנתונים האמיתיים. כפתור "איפוס נתוני ההדגמה" בפרופיל טוען אותם מחדש.

זמנית, אותה הדגמה זמינה גם באתר החי דרך הכתובת `?demo` (כפתור "מעבר לנתונים סינתטיים" במסך הכניסה ובפרופיל), כדי לבדוק את כפתור ביט מהטלפון. ההדגמה באתר החי לא מתחברת ל־Firebase ולא נוגעת בנתוני הקבוצה. מחיקת נתוני הדפדפן מוחקת את הנתונים המקומיים; יש להוריד גיבוי. כתובת אחרת/דפדפן אחר/טלפון אחר אינם חולקים נתונים מקומיים. פעולות כספיות מקומיות משתמשות ב־Web Locks כדי לסדר כתיבות בין כרטיסיות; דפדפן שאינו תומך בנעילה אינו מורשה לבצע אותן.

## פרסום ב־GitHub

מאגר: `nicomigdal/phlop`. קוד האפליקציה גלוי לציבור, אך נתוני המשתמשים והסיסמאות אינם חלק מהמאגר. פרסום GitHub Pages מתבצע ב־Actions לאחר בדיקות ובנייה. יש לבחור Settings → Pages → Source: GitHub Actions. כל push ל־main יפרסם עדכון. המסלול `/phlop/` מוגדר בתהליך הפרסום, וכל הניווט מבוסס hash כדי לתמוך ברענון דפים.

## הפעלת סנכרון חינמי בין החברים

1. פותחים פרויקט ב־[Firebase Console](https://console.firebase.google.com/) במסלול **Spark**. אין להזין כרטיס אשראי או להפעיל שירותים המחייבים Blaze.
2. מוסיפים Web App; Analytics אינו נדרש. מעתיקים את אובייקט ההגדרות הציבוריות ל־`public/firebase-config.json`, ומוסיפים `groupId: "friends"`. השדות הנדרשים: `apiKey`, `authDomain`, `projectId`, `appId`, `groupId`. אלה פרטי זיהוי ציבוריים, לא מפתח שירות. לעולם אין להוסיף service-account key או סוד למאגר.
3. Authentication → Sign-in method → Email/Password. החשבונות מבוססי טלפון: האימייל הפנימי של כל חבר הוא `<טלפון>@phlop.app` והסיסמה ב־Firebase היא `phlop-<הסיסמה באפליקציה>` (כדי לעמוד במינימום של 6 תווים). מוסיפים `nicomigdal.github.io` ל־Authorized domains.
4. יוצרים חשבון לבעל האפליקציה דרך Authentication → Users עם האימייל `0506451339@phlop.app` והסיסמה `phlop-123`, ומעתיקים את **UID** שלו. אין שמירת סיסמאות בטקסט גלוי באפליקציה.
5. יוצרים Firestore Database במצב Production. מפרסמים את `firebase/firestore.rules` בכרטיסיית Rules. אין להשתמש בכללי test/public read-write.
6. יוצרים ידנית את המסמך `groups/friends` עם השדות: `ownerUid` (מחרוזת UID משלב 4), `allowedEmails` (מערך האימיילים הפנימיים של עשרת החברים, `<טלפון>@phlop.app`), `sequence` (מספר 0), `lastEvent` (מחרוזת ריקה), `updatedAt` (timestamp נוכחי). אין לאפס את sequence אחרי השימוש.
7. מפרסמים את הקובץ המעודכן ב־GitHub. בעל הקבוצה מתחבר **ראשון** כדי ליצור את הפרופיל הראשי. יתר החברים נכנסים עם מספר הטלפון והסיסמה `123`; הכניסה הראשונה יוצרת את החשבון ומחייבת בחירת סיסמה חדשה. אין אימות SMS. שחזור סיסמה בענן נעשה בידי בעל הפרויקט ב־Firebase Console.
8. בודקים עם שני דפדפנים/מכשירים: הצטרפות, כניסה נוספת, יצירת בקשת חוב, אישור מהחשבון השני, רענון ושימור היסטוריה. רק לאחר בדיקה זו יש להסתמך על המצב המשותף.

אם פרויקט הענן לא מוגדר, האתר נשאר במצב מקומי ומציג זאת במפורש. הרשמה/אימות/שליחת קישור איפוס תלויים בשירות Firebase ובכללי הגישה. בעלי Firebase Console יכולים לנהל רשימת חברים. הרשאת אדמין בתוך האפליקציה אינה מקנה בעלות על פרויקט Firebase.

### מודל נתוני הענן

המערכת משתמשת ביומן פקודות בלתי ניתן לעריכה במקום לתת ללקוחות לכתוב יתרות ישירות. המסמך הקבוצתי שומר מספר רציף; כל פקודה נכתבת באותה עסקת Firestore עם קידום המספר. הכללים מחייבים משתמש מזוהה מקבוצת האימיילים, actorId השווה ל־UID האמיתי, זמן שרת, הוספה בלבד, ומספור אטומי ללא דילוגים. הלקוח מחשב מחדש באופן דטרמיניסטי את Sessions, BuyIns, Results, Transfers, DebtEntries, Requests, Notifications ו־Audit מתוך היומן. פקודה שאינה חוקית לפי הרשאות וכללי החישוב נדחית בעת הבנייה ואינה משפיעה על יתרות. רישום פקודות לא חוקיות בידי חבר זדוני עדיין עשוי לצרוך מכסה; זה אינו backend פיננסי חסין שימוש לרעה. כל חבר מאושר יכול לקרוא את יומן הקבוצה. אין בידוד פרטיות בין חברי אותה קבוצה.

הכללים מגינים בצד Firebase על זהות, חברות בקבוצה ושלמות ההיסטוריה; אימות העסקאות העסקי נעשה במנגנון הלקוח המשותף. זהו פשרה מתועדת לגרסה החינמית לחברים, ולא טענה למימוש מלא של אימות כספי בשרת. לשימוש רגיש או בקבוצה לא מהימנה יש להעביר את reducer לשרת מורשה.

היומן נטען במלואו לכל כניסה לקבוצה. מתאים לקבוצה קטנה; אינו פתרון לאלפי משתמשים או היסטוריה עצומה. קובצי גיבוי כוללים את מידע הקבוצה; יש לשמור אותם באופן פרטי. גיבוי מקומי אינו מוחל אוטומטית על הענן.

## בדיקות ומגבלות

`npm test` בודק חישובי אגורות, חוסר/עודף לא מתחלק, מאות תוכניות העברה, קיזוז, אישור הדדי, תשלום חלקי, הרשאות, שינוי מקביל בעת סגירה, idempotency ותיקון תוצאה אחרי תשלום. בדיקות דפדפן ידניות בוצעו גם ברוחב טלפון. בדיקות Firebase חיות ובדיקות כללי Firestore באמולטור עדיין נדרשות לפני הפעלת הענן; אין פרויקט מחובר בגרסה הראשונית.

Push לדפדפן, ייצוא XLSX, גיבוי ענן אוטומטי, ניהול מחיקות/חסימות משתמשים, עריכת כניסות קיימות ומצב ביניים שמור של ״ממתין לאישור תוצאות״ טרם מומשו. תהליך סגירת ערב הוא טיוטה מקומית עד לאישור הסופי. נתוני הדגמה זמינים רק בגרסת ההדגמה הנפרדת. האפליקציה אינה מעבירה כסף בפועל.

## קבצים עיקריים

- `src/domain.js` — חישובי כסף, הרשאות, פעולות ויומן דטרמיניסטי.
- `src/main.jsx` — מסכים וטפסים.
- `src/styles.css` — עיצוב רספונסיבי.
- `src/store.js` — אחסון מקומי, נעילת פעולות, סיסמאות מקומיות ומצב הדגמה.
- `src/cloud.js` — אימות, האזנה בזמן אמת ועסקאות Firebase.
- `firebase/firestore.rules` — כללי גישה ויומן בלתי ניתן לעריכה.
- `tests/domain.test.js` — בדיקות אוטומטיות.
- `.github/workflows/deploy.yml` — בדיקה, בנייה ופרסום.
